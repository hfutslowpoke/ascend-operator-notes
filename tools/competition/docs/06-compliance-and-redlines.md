# 合规红线与允许范围

> 下面是“星辰杯算子开发规则 v1.0”的工程化摘要，方便开发时自查。**最终以 `official/星辰杯算子开发规则_v1.0.md` 和目标赛事最新补充说明为准。**

## 1. 七条红线

| 条款 | 禁止 | 工程含义 |
|---|---|---|
| R1 | 针对 case 编程 | 必须对声明支持的 shape/dtype 域内任意合法输入正确，不能只对测试集正确 |
| R2 | NPU 计算转 host | Host 只能做 tiling、workspace、memcpy、launch、校验；不能做数值计算 |
| R3 | hash(shape)/指纹/白名单 | 不能识别具体测试用例并走特殊快路径；按 shape/tiling key 通用分派可以 |
| R4 | 结果重放 | 不能复用 golden/历史输出；不能只读不写、读无关 buffer 后 return、UB/L2 算对但不写 GM |
| R5 | 特化分支域内不全对 | 特化 key 覆盖的合法输入集合内，任意输入都要正确 |
| R6 | 空操作/纯搬运 | kernel 不能为空、不能只做 CopyData/Memcpy、不能 entry 直接 return |
| R7 | 注释/残留 | 注释可作为违规证据；最终版不能留 hash/白名单/“针对某 case”的代码或注释 |

## 2. 兜底条款

R8：任何行为等价于 R1–R7 的手法都违规，但必须能论证“等价于第 X 条”；无法论证等价性的，不构成违规。

## 3. 允许条款

### A1. Host 可以做

- Tiling 计算；
- Workspace 分配；
- 内存申请与拷贝（memcpy）；
- Kernel launch 配置；
- Shape / attr 校验。

Host 不得执行算子的数值计算，包括参考实现参与评分路径。

### A2. 按 shape / tiling key 通用分派

允许，但必须同时满足：

1. **key 范围合理**：对应可解释的 shape/tiling 分类，不能是测试用例编号的变相编码；
2. **域内任意输入正确**：该 key 覆盖的输入域内，任意合法输入都正确；
3. **有可识别的 fallback**：fallback 必须产出数值正确的结果，不能 fallback 到 host、不能返回错误码、不能是永远走不到的 `default: assert(0)`。

## 4. 开发过程 vs 最终提交

- 红线针对**最终提交版本**判定；
- 开发过程中的 host 先行实现、device 桩函数、临时 return 不构成违规；
- 但最终提交必须清理干净；
- 赛后可能对排名前列的 kernel 做 fuzzing；
- 违规成绩可追溯作废，删除提交也不能保留违规高分。

## 5. 处罚梯度（摘要）

| 情形 | 处理 |
|---|---|
| 单题首次轻违规（R6/R7 等） | 提交无效 + 警告 + 脱敏公示；重提合规版本，按合规版本重算 |
| 单题严重违规（R1/R3/R4 等） | 取消该题成绩 + 脱敏公示；重提合规版本，按合规版本重算 |
| 多题违规且属 R1/R3/R4 | 取消全部成绩、撤销排名、全量重排；可重提合规版本 |
| 多题违规但属 R6/R7 等 | 取消相关题成绩，不取消全部；可重提合规版本 |
| 违规/已删/非 Pass | 成绩作废；重提合规版本重算 |

## 6. 提交前合规自查

- [ ] 没有 `if (shape == exact_case)`、`hash(shape)`、白名单、测试用例编号分支
- [ ] 没有 host 侧数值计算参与输出
- [ ] 没有预存 golden、历史输出、结果重放
- [ ] 没有空 kernel、纯搬运、entry 直接 return
- [ ] 所有特化分支在域内任意合法输入上都正确
- [ ] fallback 真实可用，产出正确结果
- [ ] 输入只读，输出写回 GM
- [ ] 最终版没有“针对某 case”的注释、调试代码、临时快路径
- [ ] CPU 参考实现只用于自测，不在评分路径
- [ ] 随机/fuzz/边界用例通过，不只是公开样例

## 7. 一句话

**可以按通用 shape 分类做性能分派，但不能识别具体测试用例；可以让 host 做调度，但不能让 host 做数学；可以保留参考实现自测，但不能让它参与评分。**
