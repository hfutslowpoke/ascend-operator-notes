## 算子说明

### 算子功能

车载 LiDAR 的局部点云分组有时使用带方向和高度范围的圆柱，而不是各向同性的球。Cylinder Query 按查询中心和局部坐标变换把参考点变到圆柱坐标系，再用径向距离和轴向高度筛选，用于柱状区域构建、三维目标检测和局部几何聚合。

`CylinderQuery` 对每个查询中心及其 3×3 变换矩阵，在参考点云中查找有限高度圆柱内的点索引。每个查询最多返回 `nsample` 个点。

计算规则（`rot[b,m]` 为 row-major 的 3×3 矩阵；半径和高度边界都用严格比较）：

```
Δ = xyz[b,k] - new_xyz[b,j]
[x_l, y_l, z_l]^T = rot[b,j]^T @ [Δx, Δy, Δz]^T
命中当且仅当 y_l² + z_l² < radius² 且 hmin < x_l < hmax
按 xyz 的输入索引从小到大扫描，不按距离排序
只保留最先出现的 nsample 个命中点
命中数 ≥ nsample：返回前 nsample 个命中索引
命中数为 1 .. nsample-1：尾部重复第一个命中索引
命中数为 0：该行输出全 0
```

`rot` 是一般有限 3×3 线性变换，不要求正交，按 row-major 存储。JSON 的 min/max 范围无法生成正交矩阵；官方 GSNet/AnyGrasp 的 `cylinder_query` 使用 `rot` 的列与 `delta` 做内积，即严格按 `rot^T @ delta` 执行（等价于行向量 `delta @ rot`），不是 `rot @ delta`。

### 输入输出规格

| 张量 | 形状 | 数据类型 | 含义 |
|------|------|---------|------|
| xyz | [B,N,3] | float32 / float16 | 被查询的参考点云 |
| new_xyz | [B,M,3] | float32 / float16 | 圆柱中心 |
| rot | [B,M,3,3] | float32 / float16 | row-major 局部坐标变换矩阵 |
| idx | [B,M,nsample] | int32 | 圆柱邻域点索引 |

维度约束：B、N、M 为正整数，N ≥ 1；三个输入的 batch 一致，坐标最后一维为 3，rot 固定为 [B,M,3,3]。`radius > 0`，`hmin < hmax`，`1 ≤ nsample ≤ N`（与官方 Ascend CylinderQuery 约束一致）。常规输入范围为 [-1,1]。所有输入值必须有限，不支持 NaN、+Inf、-Inf。输出索引为 int32，范围为 [0,N-1]；无命中时的 0 是占位值。

数据类型约束：支持 float32、float16 两种浮点输入，同一组 Case 内 xyz、new_xyz、rot 使用相同数据类型。局部坐标变换、径向/轴向判断与阈值比较统一按 float32 语义执行：float16 输入需先无损转换为 float32，再参与矩阵乘和严格比较。输出恒为 int32。`input_desc`/`output_desc` 的 `datatype` 按两组配置逐项声明：xyz、new_xyz、rot 为 `["float32","float16"]`，idx 为 `["int32","int32"]`；第 1 项对应 float32 配置，第 2 项对应 float16 配置。

NPU 测试集共 18 组：float32、float16 各 9 组；每种数据类型下按 Small、Medium、Large 三种规模各设计 3 组。两种数据类型复用同一套 Shape 与属性，具体如下：

规模划分与组合规则：

- xyz 的点数 N：Small 为 16–128，Medium 为 512–1024，Large 为 2048；
- new_xyz 的查询数 M：Small 为 4–8，Medium 为 32–64，Large 为 128；rot 的 M 维与 new_xyz 一致；
- 单个 Case 的规模取其最大输入张量所属的规模；
- 9 组 Case 按 Small、Medium、Large 各 3 组设计；
- 多输入算子的 N 与 M 独立设计，覆盖 N Medium/M Small、N Medium/M Large、N Large/M Medium 等不同搭配，而不是所有输入同步缩放。

### 属性参数

| 参数 | 类型 | 默认值 | 含义 |
|------|------|--------|------|
| radius | float | 0.05 | 圆柱半径，必须有限且大于 0 |
| hmin | float | -0.02 | 圆柱轴向下界，轴向坐标为局部 x |
| hmax | float | 0.04 | 圆柱轴向上界，必须大于 hmin |
| nsample | int | 32 | 每个查询最多返回的点数，必须满足 1 ≤ nsample ≤ N |

每种数据类型的 9 组测试分别传入上表中的 radius、hmin、hmax 和 nsample，不使用默认值代替 Case 中的属性。

### 功能示例

Case 2 中 xyz 与 new_xyz 均在 `[-0.001,0.001]` 内，delta 各分量绝对值不超过 0.002；rot 在 `[0.999,1]` 内，局部坐标各分量绝对值不超过约 0.006，满足径向平方 < `0.1²` 且 hmin<0<hmax，全部参考点命中；N=nsample=16，每个查询的输出为索引 0 到 15。Case 6 中 delta 各分量约为 2，rot 约为 1，局部坐标约为 (6,6,6)，径向平方约 72，大于 `0.1²`，高度约 6 也不在 (-0.1,0.1) 内，输出全 0。

### 任务要求

针对不同 N、M、nsample 以及 float32/float16 两种输入数据类型，设计算子逻辑，保证 int32 索引与 CPU Reference 逐元素一致（atol = 0、rtol = 0）。`rot^T @ delta` 的乘法方向、严格半径和高度边界、输入索引 first-K 以及填充规则都属于正确性定义。float16 输入必须转换为 float32 后再做矩阵变换与阈值比较，不能直接用低精度比较而产生索引偏差。

充分发挥系统带宽能力和并行计算能力，算子性能更优。12 组组合都要对每个查询中心做局部坐标变换和圆柱判断；某个查询已经收集满 nsample 后可以停止扫描该查询。应优化矩阵变换、径向与轴向筛选、查询点并行和点坐标复用。不能靠跳过变换、减少查询或固定输出索引来缩短时延。性能以 CannJudge 统一环境下逐 Case 测量的算子执行时延为准。

**禁止事项**：禁止回退到 CPU，禁止把圆柱查询改成球形查询，禁止改变 `rot^T @ delta` 的乘法方向、严格边界、first-K 顺序和填充规则，禁止跳过局部坐标变换或部分查询，禁止在 float16 下用低精度阈值比较替代 float32 语义。
