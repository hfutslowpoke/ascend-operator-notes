# 数学顺序与赛事约束

本页整理本次题目和会话收到的官方要求。后续比赛应重新核对当届规则，不把本次限制自动当成硬件限制。

## 本题数学链

实际累计 `group_list` 确定每行专家，允许空专家。对每个有效输出元素计算完整 true-K 的 INT8×INT8 INT32 点积/归并；然后转 FP32 反量化并执行 GELU，最后转 FP16。不得在 GELU 前把反量化结果转成 FP16。允许的等价实现或函数逼近仍需满足当届精度条款。

输出为连续 ND `(M,N)`、FLOAT16，保持原始输入行序；不得增加 padding 行、空专家占位行或重排最终专家顺序。每个有效输出元素均由本次调用实际写入，不依赖输出初值。

INT8 输入转 half 可精确表示全部输入值，与“反量化结果在 GELU 前转 half”是不同步骤；但仅看到输入转换正确，不足以证明后续长 K 累加仍符合 INT32 语义。完整计算链应逐阶段审阅。

## Host 与 Device

Host 仅做参数校验、shape 推导、tiling 与启动配置。不得读取输入张量数据做计算、重排，或完成向量/矩阵计算后把结果交给 kernel。

Kernel 完成完整计算流程。一次调用只允许一个 kernel；预处理、实际分组描述符、打包、计算、GELU、写回需要在该 kernel 内完成并正确同步。内部多阶段不是多次 kernel 启动。

## 不允许的手段

- 硬编码、预存本应由算子产生的固定结果，按用例或数据生成规律跳算；
- 仅逐条匹配测试 case 编写专属实现，包括改成某个唯一标识符继续识别原 case；
- 写标记跳过计算，利用旧输出或未初始化内存；
- 干扰精度检查、计时，注入空 kernel，识别预热轮次，把实际计算移出计时；
- 在多轮评测间持久缓存计算结果；
- 将一次计算拆成多次 kernel。

按 K=1、N=1、对齐程度、容量不等式或一般工作量族选择不同算法，有数学与硬件上的理由；实际数据相关处理仍由 Device 执行。区间条件并不会自动使逐 case 实现变成通用实现，需要看其设计和覆盖是否成立。
